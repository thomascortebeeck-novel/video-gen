- **Style bleeds across a whole take** (measured 2026-08-24, task cgt-20260824200801-45d2m): a 13s multi-stage generation whose reference set was 3 cartoon pages + 1 photo of an empty room came back **entirely cartoon**, including the two stages the prompt marked photoreal. Seedance weights the reference images far above per-stage [VISUAL STYLE] wording. A photoreal→animated transition inside ONE generation therefore needs the live-action look carried by its own reference image of *people* (blocked by the face filter) — so in practice split it: photoreal section as its own generation, then extend/bridge into the animated one. Also observed: a late "she climbs onto the animal and rides away" beat was flattened into "stands beside it" — mount/dismount actions need their own stage with the physical steps spelled out, or a first-frame image already showing the character mounted. **Fix confirmed 2026-08-24** (task cgt-20260824215122-nvzxm): giving the mount its own stage with each physical step named ("takes a handful of mane in both hands, lifts her right leg up and over its back, settles ASTRIDE it") **plus** a `reference_image` that already depicts the mounted pose produced a correct mount in a 4s take. Either alone had failed; together they hold.
- **Zero-reference text-to-video is the reliable photoreal path** (confirmed 2026-08-24, task cgt-20260824210023-qdgxd): the same brief that came back fully cartoon with 3 drawn refs + 1 photo rendered perfectly photoreal at 5s/1080p with **no media references at all** ($2.62). Corollary to the style-bleed finding: when a shot must be live-action and every asset on hand is a drawing, attach nothing — describe the cast in `continuity` instead, and match a drawn cast by **hair and wardrobe**, which is what carries recognition at 15-second lengths. Ark's grade skews cool and underlit; a curves + saturation pass in post recovers the warm-lamp-vs-cool-screen look without a re-roll.
- **An extend anchors style, so one drawn ref can ride along safely** (proven 2026-08-24, task cgt-20260824212746-ccmtx): extending a photoreal clip (`omni_reference_task_type:"extend"`, source as `@Video 1`) with a cartoon storybook page attached as `@Image 1` kept everything outside the tablet screen fully photographic — real hands, real hair, real bedding — while reproducing the drawn page *and its title lettering* correctly inside the glass. The source video outweighs a drawn `reference_image`, which a plain omni-reference create does not. So: mixed photoreal/animated frames are reachable via extend, not via a fresh multi-ref generation. 4s @1080p + 1 ref video + 1 image = 437,400 tokens ≈ $4.68. A `CUT to behind …` instruction inside the extension executed correctly and did not replay earlier action.
- **Every generation invents its own narrator voice** (2026-08-24): Seedance generates non-diegetic VO from the `[AUDIO]` block, and the voice/accent is re-rolled per task. An **extend** carries the source clip's voice forward; a **fresh generation does not**, so any hard-cut scene boundary is an audible voice change. Since a photoreal→animated boundary *cannot* be an extend (the extend anchors style to its source), a multi-scene film mixing both looks can never hold one voice from the model alone. Fix: suppress model VO and lay a single narration track over the finished cut in post — it also fixes the score, which likewise restarts per generation. Same applies to the music bed under an end card composited in ffmpeg (it is silent unless you supply it).
- **Costs** (720p): video ≈ $0.231/s on ModelArk (tokens = W×H×s×24/1024 × $10.70/M); 480p ≈ $0.10/s, 1080p ≈ $0.52/s measured (13s 1080p with 4 reference images = 633,825 tokens ≈ $6.78; the older $0.41/s figure was low). Seedream images ≈ $0.05–0.09 each. Only successful generations bill.

## GCP org quirks (aiwebatelier.com org)

- Compute SA gets **no default roles** — new projects need manual grants: `cloudbuild.builds.builder` (else builds fail), `datastore.user`, `storage.objectAdmin`, `logging.logWriter`, per-secret `secretmanager.secretAccessor`.
- **Domain Restricted Sharing** org policy blocks `allUsers` — callable functions need a project-level override of `iam.allowedPolicyMemberDomains` (allowAll) + `run.invoker` for `allUsers` on each service. Thomas holds org-policy-admin; the override persists on aiwebatelier-spine.
- First deploys can hit the gcf-v2-sources bucket 409 race (retry) and hosting uploaded-but-not-released (run `deploy --only hosting`).
- **The deployer SA can ship function CODE but cannot make a NEW function callable** (hit 2026-08-24 deploying verifyScene/planRegeneration/regenerateScene/buildPrevizScript/ingestPreviz). `roles/editor` has no `run.services.setIamPolicy`, so `firebase deploy` updates existing functions fine but fails on any *newly added* callable with `Failed to set the IAM Policy on the Service …` / `Failed to set invoker function …`. The function still deploys ACTIVE with the right config — it is simply not publicly invokable, so the client gets 403. **The org policy is NOT the cause here** — `constraints/iam.allowedPolicyMemberDomains` is `allValues: ALLOW` on this project; it is purely the SA's role. Permanent fix, as an owner (`gcloud auth login` first, since the org session policy expires user OAuth within hours): `gcloud projects add-iam-policy-binding aiwebatelier-spine --member=serviceAccount:deployer@aiwebatelier-spine.iam.gserviceaccount.com --role=roles/run.admin`. One-off alternative per function: `gcloud run services add-iam-policy-binding <lowercased-function-name> --region=europe-west1 --member=allUsers --role=roles/run.invoker` (service name = the function name **lowercased**). **Granting the role does NOT fix the already-deployed functions by itself**: a follow-up `firebase deploy --only functions` reports `Skipped (No changes detected)` and never retries the bindings, so set them manually once (verified 2026-08-24 — all five went from 403 to a correct 401 afterwards). Reachability test that distinguishes the two failures: `curl -X POST https://europe-west1-aiwebatelier-spine.cloudfunctions.net/<fn> -d '{"data":{}}' -H 'Content-Type: application/json'` — **401** means reachable and the function rejected the missing token (correct); **403** means Cloud Run is still blocking. **A functions error also aborts the deploy before hosting releases** — always follow up with `deploy --only hosting`.
- **An in-process call bypasses all of this.** `autoVerify` runs inside `runGenerateScene`, so automatic verification works even while the `verifyScene` callable itself is 403 — only the buttons that call it over HTTPS are affected. Worth remembering when triaging: "the feature works but its button doesn't" is the signature of a missing invoker binding, not broken code.
- **Headless deploy auth** (since 2026-08-23): the org's session policy invalidates user OAuth (gcloud AND firebase-tools) within hours — non-interactive refresh fails with `invalid_rapt`, and firebase-tools then dies with a misleading "resolving hosting target" assertion. firebase-tools ignores `authorized_user` ADC files (needs a service-account key). Fix in place: SA `deployer@aiwebatelier-spine.iam.gserviceaccount.com` (roles editor + firebasehosting.admin + iam.serviceAccountUser), key at `~/.config/aiwebatelier/deployer-key.json` — deploy with `GOOGLE_APPLICATION_CREDENTIALS=~/.config/aiwebatelier/deployer-key.json npx firebase deploy …`. Key creation required a temporary project override of `constraints/iam.disableServiceAccountKeyCreation` (re-enforced afterwards; existing key unaffected; propagation takes ~1 min — retry). Firestore/Storage/GSM REST work off `gcloud auth print-access-token` after the user reauths interactively.

## Casting architecture (since 2026-08-23 — the moderation era)

- **Characters are anchored by a SCREEN TEST, not angle images**: `runGenerateScreenTest` generates a short text-to-video casting clip (slow turn + one spoken line, `buildScreenTestPrompt`, ≤8s, audio on) stored at `screen_tests/{subjectId}/v{n}.mp4` on `SubjectDoc.screenTest`. Text-to-video has no input images → passes the platforms' real-person filter. The clip carries identity AND voice; the user recasts until happy (mirrors Sora cameos / Kling video-trained characters — video-as-identity is industry practice).
- Scenes reference characters with kind **`subject_video`** (@videoN, media 'video' in `resolveReferenceTags`; adapters attach as plain `reference_video` / fal `video_urls`, ≤10). Products keep `subject_angle` image refs (product images pass moderation). Dialogue voice tag falls back to the speaker's `subject_video` tag when no `voice_audio` ref exists.
- Moderation auto-recovery in `runGenerateScene` (ark): drop flagged image refs → if no character anchor remains and no screen test attached, fall back to the scene's latest take as reference video → else fail with guidance.
- **Extend scenes drop `subject_video` refs before the prompt is built** — the adapters attach exactly one `reference_video` (the clip being extended, which already carries identity + voice), so keeping screen-test tags would name refs that are never sent. Prompt and payload must always be built from the same filtered list.
- Production tab: per-scene **take gallery** (every version clickable, newest is the one used in the final film) and a **"How was this generated?"** panel — each reference with its @tag, thumbnail/clip, use/ignore lines, plus engine params, job id and the verbatim assembled prompt.
- Character angle-image generation still exists for legacy projects/products but the UI routes characters to screen tests.

## Camera previz (Blender — since 2026-08-24)

- **Complex camera moves are blocked out in 3D before any credits are spent.** The director marks every scene `cameraComplexity: simple|complex` and, when complex, emits a structured `CameraPlan` (blocky proxy set + keyframed camera, metres, Z-up). `shared/previz.ts` renders that plan into a **Blender Python script** — plain deterministic code, never model-authored Python. The Blender **MCP server is deliberately not used in the product**: it needs a live Blender + socket (unreachable from Cloud Functions) and blender.org itself warns it executes LLM code unguarded. `blender -b -P previz_{sceneId}.py` runs locally, free, in seconds.
- The rendered MP4 is uploaded back; `runIngestPreviz` samples it at 1 fps, tiles a contact sheet, and Claude vision **reads the actual frames** into a timed camera map (`0-6s — holds, slow push in / 6-12s — through the glass, turns right onto the vendor`). The map goes into `[CAMERA AND PERFORMANCE]` verbatim plus the constant-speed/no-roll default line. `checkStageTiming` then flags stages that fall outside every camera window, and dialogue that straddles a camera move — a beat only lands if the camera is on it when it happens.
- **The map is TEXT, and that is the point.** Reference *images* are token-free on ModelArk while each attached `reference_video` adds ≈ +1× base tokens — the measured series 172.8k → 346.5k → 519.3k (base → +1 ref video → +2 ref videos +1 image) shows the image adding **zero**. Characters already spend their one reference video on the screen test, so a previz *video* would roughly double every complex scene. Per-scene `previz.feed`: `map_only` (default, free) → `map_plus_sheet` (free, but grey blocks can bleed — see the style-bleed finding) → `attach_video` (opt-in, ≈ +$1.85 per 8s @720p).
- **Previz is optional and configurable in two places** (`ProjectInput.previz`: `off | auto | always`, default `auto`): the New-project form, and — changeable at any time — the selector on the **Scenes** section header of the Briefing tab. `off` hides the previz panel entirely; `always` makes the director plan a move for every scene (re-plan the briefing to apply it). `previzAllowed()` in `shared/previz.ts` is the single gate.
- Previz and scene share ONE clock: `runBuildPrevizScript` re-times the plan to `scene.durationSec` on every build.
- Extend scenes now drop **every** video ref (was: only `subject_video`) — the adapters attach exactly one `reference_video` (the clip being extended), so an attached previz would be named in the prompt and never sent.

### Blender facts (verified on Blender 5.2.0 LTS / macOS, 2026-08-24)

- **The macOS build has NO FFmpeg video output** — `image_settings.file_format` offers image formats only (`AVIF, JPEG, OPEN_EXR, PNG, WEBP, BMP, CINEON, DPX, IRIS, JPEG2000, HDR, TARGA, TARGA_RAW, TIFF`). Worse, the **static RNA enum still advertises `FFMPEG`**, so `'FFMPEG' in bl_rna...enum_items` returns true on a build that cannot do it. The only reliable probe is **the assignment itself, in a try/except**. The generated script falls back to rendering a PNG sequence and muxing with the system ffmpeg (`shutil.which`, plus the Homebrew paths); if ffmpeg is missing it leaves the frames and prints the exact mux command.
- Frame count: `frames 1..DUR*FPS` is exactly DUR seconds. `round(t*fps)+1` for the last keyframe gives one frame too many (289 frames = 12.04s for a 12s clip) — keyframes use `frame_at()`, but `frame_end` must be `round(DUR*FPS)`.
- **Workbench** engine renders headless on CPU with no lighting rig; `TRACK_TO` on an animated empty (`TRACK_NEGATIVE_Z` / `UP_Y`) keeps the horizon level for free, which *is* the "no camera roll" rule. LINEAR f-curve interpolation everywhere gives the constant speed the prompting guide asks for. `all_fcurves()` handles both legacy `action.fcurves` and the 4.4+ slotted-action layout.
- Cost/speed measured: **12s at 640×360 = ~10s wall clock, free.** Blocky figures need contiguous segments (legs `[-0.50h, 0.02h]`, torso `[0.02h, 0.37h]`, head `[0.37h, 0.50h]`) or the head visibly floats.
- **ffmpeg `drawtext`**: the Homebrew ffmpeg 9.0.1 on this Mac has **no** libfreetype, but the `ffmpeg-static` bundled in functions **does** — `buildContactSheet` stamps each tile with its timecode and silently degrades to unlabelled tiles when the filter is missing.

## Production QC — verify + re-roll (since 2026-08-24)

- **Verification runs automatically on every finished take** — `autoVerify` fires at the end of `runGenerateScene` AND `runRefreshScene`, after the take is saved and marked `completed`, so the clip appears in the UI immediately and the verdict lands a moment later. It is **structurally unable to throw** (nested try/catch, even around `setProgress`): it sits inside `runGenerateScene`'s try, so an escaping error would mark a paid, successful generation as failed. Skipped when there is no `ANTHROPIC_API_KEY` or in mock mode — an automatic mock verdict on every scene is noise, not signal. If the function dies mid-read the verdict stays `running`; the UI shows that as "interrupted" after 10 minutes rather than spinning forever, and the manual button recovers it. `refreshScene` went 300s → 540s because it now verifies too.
- **Every take can be graded against its plan before anyone spends.** `runVerifyScene` samples the clip (2 fps under 12s, else 1 fps, ≤24 frames), transcribes the audio, and has Claude vision score it. **~$0.03–0.10 per take against a $1.85–6.78 re-roll — roughly 1–3%**, which is the whole argument for running it by default.
- **Claude cannot hear** — no model accepts audio input — so dialogue is checked via **ElevenLabs Scribe** (`POST /v1/speech-to-text`, multipart, field `file`, `model_id=scribe_v2`, `diarize`, `timestamps_granularity=word`, `tag_audio_events`) on the key already held for voice casting. `functions/src/stt.ts`. Missing key ⇒ picture-only verdict, never a failure.
- **The criteria are this repo's own recorded failures**, not generic QC (`shared/verify.ts`): `style_match` (cartoon bleed), `beat_coverage` (the flattened mount), `onscreen_text` (respelled insert cards), `camera_vs_plan` (drift off the previz map), plus identity/wardrobe/dialogue/lip-sync/audio/pacing/artifacts. Criteria that cannot apply are **skipped, not guessed** — `criteriaFor(scene)` gates on the scene doc.
- **Every finding carries a `fixKind`** — `edit` (free) · `prompt` · `reference` · `accept`. That routing is the point: about half of what goes wrong is editorial and costs nothing, so the verdict names the cheap lever before the expensive one.
- **A note never rewrites the prompt.** `patchSceneFromNote` returns **field-level patches** (`stages[2].action`, `visualStyle`, …) applied by `applyScenePatches`; unknown paths are rejected, not coerced. This is what protects the verbatim-reuse convention — `continuity`/`keepConsistent` are flagged `SHARED_TEXT_FIELDS` and shown in red in the diff, because rewording them is how a character drifts between scenes.
- **The re-roll is split in two so the approval gate is real**: `planRegeneration` (free — computes the patch, the assembled prompt and the price, writes nothing) then `regenerateScene` (spends). The UI shows the diff, the prompt and the cost before the only button that bills. Cost maths lives in `shared/cost.ts`, validated against measured billing (8s 720p = exactly 172,800 tokens; 13s 1080p ≈ $6.78).
- **Verdicts are per take, not per scene** — `verdict.takePath` is compared against `scene.videoPath`, so an old verdict shows as `stale` rather than being silently deleted. Take chips carry their score and the note that produced them.
- **ffmpeg's `image2` demuxer picks the decoder from the FILE EXTENSION, not the content** — a JPEG written as `.png` dies with "Invalid PNG signature". `buildContactSheet` sniffs the magic bytes and names its sequence accordingly. Verification frames are **JPEG**: 24 frames of 640px PNG is ~4.6 MB, the same as JPEG is ~0.29 MB — **16× smaller** for identical vision billing (which is by dimensions).

## Audio stems — measured, works (probe 2026-08-24)

- **Dialogue separates cleanly from Seedance-generated audio.** Demucs `htdemucs` on real Pricey takes: a spoken clip put **99.8% of its energy in the vocals stem** (drums −50 dB, bass −75 dB, other −60 dB); music-only clips put **0.5–4.5%** there, so it does not hallucinate speech. Speech-gating separation 26–48 dB. **Reconstruction error −47 to −59 dB** — the four stems sum back to the original, so it is a *lossless decomposition*: a remix can always return to the source.
- Speed/cost: ~**realtime on CPU** for our 4–15s clips (6.08s clip in 6.3s), free, local. Needs Python **3.13** — `pip install demucs` has no wheels for the 3.14 that is `python3` on this Mac; `/opt/homebrew/bin/python3.13` is installed and works (torch 2.13, MPS available).
- **What Demucs does NOT give is music vs ambience** — its `drums`/`bass`/`other` split is music-oriented, and film ambience lands across all three. The true dialogue/music/effects split is a named task, **cinematic audio source separation (CASS)**; **Bandit** (Apache-2.0, pretrained checkpoints on Zenodo, 416–828 MB peak, CPU-viable) is purpose-built for it. So: dialogue-vs-bed is proven today; the third lane needs Bandit.
- `showwavespic`, `xfade`, `acrossfade`, `sidechaincompress`, `loudnorm`, `zoompan`, `curves`, `eq`, `overlay`, `tile` and `drawtext` (with libfreetype) are **all present in the bundled `ffmpeg-static` 6.0** that Cloud Functions runs — the editor needs no new binary.

## How the Pricey promo was actually cut (reference workflow)

- Entirely **ffmpeg on the CLI**, no After Effects and no NLE — proven by the file's own tags (`encoder=Lavf63.1.101` / `Lavc63.1.101 libx264`, i.e. Homebrew ffmpeg 9.0.1; the source scenes carry `Lavf58.76.100`, the bundled `ffmpeg-static`). A Python build script (`assemble_final.py`) ran **27 ffmpeg invocations** and was re-run end to end on each note — v1→v7 in about an hour.
- House moves worth keeping: stills pushed in **2% over 2s** via `zoompan` with a 0.25s `fade` in; `afade=t=out:d=0.5` before any cut to silence; `crf 17`, `preset slow`, `+faststart`; 9:16 delivered as a centre crop of the same master; grade via `eq` + `curves`.

## Web app design system (web/src/styles.css)

- **Never write a raw Tailwind colour** (`zinc-800`, `amber-500`, …). Every colour is a semantic
  token: `ground / surface / surface-2 / line / line-soft`, `ink / ink-2 / muted / faint`,
  `accent / accent-ink / accent-soft`, `cool / cool-soft`, `ok / bad` (+ `-soft`). They are declared
  as `--c-*` custom properties and exposed to Tailwind via `@theme inline`, which is what lets the
  theme swap at runtime.
- **Three theme states.** Bare `:root` = light; `@media (prefers-color-scheme: dark)` guarded as
  `:root:not([data-theme="light"])` = OS dark; `:root[data-theme="dark"]` = explicit choice. The
  `ThemeToggle` (light / system / dark) stamps `data-theme` on `<html>` and stores it under
  `studio-theme`; `index.html` re-stamps it before first paint so there is no flash.
- Component classes (`.card`, `.well`, `.btn*`, `.input`, `.label`, `.chip*`, `.eyebrow`,
  `.codeblock`) live inside `@layer components` so plain utilities in JSX still override them.
  `tnum` is an `@utility` so it works inside `@apply` too.
- Type: **Instrument Sans** for UI, **JetBrains Mono** for anything technical (timecodes, ids, tags,
  prompts, section eyebrows, field labels). Loaded from Google Fonts in `index.html`.
- One primary (amber) button per section — the section-level action. Per-card actions are `btn-ghost`.

## Conventions

- Sheets' text blocks are reused **verbatim** across prompts — never reword identity/wardrobe/materials between scenes.
- One scene = one Seedance generation (4–30s); long films = multiple scenes stitched (hard cut / frame bridge / extend). Voiceover lines go in stage actions as `Voiceover — her/his voice: "…"` plus "mouths never sync" in continuity; lip-synced dialogue uses the stage `dialogue` field.
- Storage layout + Firestore paths: `shared/types.ts` (`storagePaths`, `collections`). Scene videos version as `v{n}.mp4`; every provider result is copied to Storage immediately.
