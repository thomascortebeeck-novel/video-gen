## Hard-won provider facts (do not rediscover)

- **ModelArk video** `dreamina-seedance-2-5-260628`, `POST {ARK_BASE_URL}/contents/generations/tasks`, content items carry roles (`reference_image|reference_audio|reference_video|first_frame|last_frame`). First/last-frame & extension need `ratio:"adaptive"`; extension needs continuation keywords + `omni_reference_task_type:"extend"`. Result URLs valid 24h/100 downloads — pipeline persists to Storage immediately. Models must be **activated** in the Ark console; Seedance 2.5 needs a **$30+ balance**. `BalanceNotEnough`/`ModelNotOpen` errors = console-side fixes.
- **Seedream 5.0 Pro images** `dola-seedream-5-0-pro-260628`, sync `POST /images/generations`, `image` = ref URL array (≤10), explicit sizes (`1536x2048` etc., area ≤ 4,624,220 px), `watermark:false`. It **rejects `sequential_image_generation`** entirely (Lite-only). Rate-limits fresh accounts hard → angle generation runs sequentially with backoff retries (pipeline.ts CONCURRENCY=1 for ark).
- **Reference tags**: internal format is lowercase `@image1` (Dan Kieft); adapters normalize on the wire — `@Image 1` for ModelArk, `@Image1` for fal. **Binding is by attachment order per modality** (Nth image = @Image N) — tags and URLs are built from one ordered list, so they cannot drift.
- **ModelArk privacy filter**: Seedance *video* create-task rejects reference images with realistic faces — `InputImageSensitiveContentDetected.PrivacyInformation`, listing offending `content[i]` slots — **even for AI-generated faces**. The filter runs before the prompt is read (prompt disclaimers useless). **TIGHTENED PLATFORM-SIDE 2026-08-23**: on 08-22 full-body angles passed (only close-ups failed); a day later ALL realistic character images fail — including Seedream re-prints, film-graded variants, and frames extracted from ModelArk's own completed output. `reference_video` with faces still passes (both plain and extend mode), and Seedream/GPT *image* endpoints still accept face refs. `runGenerateScene` auto-recovers in order: drop exactly the flagged refs → if no subject image survives, attach the scene's latest take as a plain `reference_video` identity anchor (`identityVideoUrl`, @video1 line injected into the prompt) → else fail with a clear message. Stores `generation.moderationNote`. Rejected creates bill nothing; running tasks cannot be cancelled (DELETE → 409, only `queued` can). NOTE: each attached reference video adds ≈ +1× base tokens (8s 720p: plain 172.8k ≈ $1.85; 1 ref video 346.5k ≈ $3.71; 2 ref videos + 1 image 519.3k ≈ $5.56). **fal.ai enforces the same likeness policy** (verified 2026-08-23 with a real job: queue accepts the submission, the job then fails `content_policy_violation` — "may contain likenesses of real people"; no safety toggle exists in the endpoint schema; failed jobs bill nothing). Conclusion: the people-image block is ByteDance-wide for Seedance-2.5 API access, not BytePlus-specific. Working paths: video-identity references / extends (proven), BytePlus ticket / verified real-person program, or Higgsfield's consumer UI (manual, no API).
- **ModelArk extension** (verified by probe 2026-08-23, task cgt-20260823032535-5bb46): output = **continuation only** (requested `duration` of NEW content, not merged with the source) → assembly concats extend joins with no trim, which the pipeline already does. `reference_image` items are accepted alongside the `reference_video`; a **hard cut to a new location works inside an extension** while carrying identity, voices and score (this is the voice-consistency mechanism across scenes). Ratio `adaptive` follows the source video's resolution.
- **Insert cards**: on-screen text (phone messages, menus, signs) is modelled as `EnvironmentDoc.type: 'insert_card'` — a flat full-frame graphic with the EXACT text, generated upfront (GPT Image 2 excels at this) and attached to the scene with "reproduce exactly, never respell" grammar. The Claude director plans them via `environments[].type`; `buildEnvironmentPrompt` branches on the type.
- **fal.ai**: queue API `queue.fal.run/bytedance/seedance-2.5/{variant}`; `duration` is a STRING enum ("4".."30"|"auto"); no seed input; r2v supports `audio_urls` (voice refs) and `video_urls` (extension via continuation prompt); results expire ~1h.
- **GPT Image 2** (`gpt-image-2`, verified 2026-08-23): sync `POST /images/generations` (JSON) or `/images/edits` (multipart, refs as `image[]` parts in order, ≤16) → `data[0].b64_json`. Needs OpenAI **Organization Verification** (done). Arbitrary sizes (edges ×16, ≤3840, ratio ≤3:1) — we use 1152x1536 for 3:4. Accepts face refs (identity edits are its strength); input fidelity always high, no param. Token-billed: quality high ≈ 4× medium (`OPENAI_IMAGE_QUALITY`, default high ≈ $0.36 @1152×1536, medium ≈ $0.09). Prompts rewrite `@imageN` → "reference image N". Up to ~2 min/image; CONCURRENCY=2.
- **Costs** (720p): video ≈ $0.231/s on ModelArk (tokens = W×H×s×24/1024 × $10.70/M); 480p ≈ $0.10/s, 1080p ≈ $0.41/s. Seedream images ≈ $0.05–0.09 each. Only successful generations bill.

Fix in place: SA `deployer@aiwebatelier-spine.iam.gserviceaccount.com` (roles editor + firebasehosting.admin + iam.serviceAccountUser), key at `~/.config/aiwebatelier/deployer-key.json` — deploy with `GOOGLE_APPLICATION_CREDENTIALS=~/.config/aiwebatelier/deployer-key.json npx firebase deploy …`. ## Casting architecture (since 2026-08-23 — the moderation era)

- **Characters are anchored by a SCREEN TEST, not angle images**: `runGenerateScreenTest` generates a short text-to-video casting clip (slow turn + one spoken line, `buildScreenTestPrompt`, ≤8s, audio on) stored at `screen_tests/{subjectId}/v{n}.mp4` on `SubjectDoc.screenTest`. Text-to-video has no input images → passes the platforms' real-person filter. The clip carries identity AND voice; the user recasts until happy (mirrors Sora cameos / Kling video-trained characters — video-as-identity is industry practice).
- Scenes reference characters with kind **`subject_video`** (@videoN, media 'video' in `resolveReferenceTags`; adapters attach as plain `reference_video` / fal `video_urls`, ≤10). Products keep `subject_angle` image refs (product images pass moderation). Dialogue voice tag falls back to the speaker's `subject_video` tag when no `voice_audio` ref exists.
- Moderation auto-recovery in `runGenerateScene` (ark): drop flagged image refs → if no character anchor remains and no screen test attached, fall back to the scene's latest take as reference video → else fail with guidance.
- Character angle-image generation still exists for legacy projects/products but the UI routes characters to screen tests.

## Conventions

- Sheets' text blocks are reused **verbatim** across prompts — never reword identity/wardrobe/materials between scenes.
- One scene = one Seedance generation (4–30s); long films = multiple scenes stitched (hard cut / frame bridge / extend). Voiceover lines go in stage actions as `Voiceover — her/his voice: "…"` plus "mouths never sync" in continuity; lip-synced dialogue uses the stage `dialogue` field.
- Storage layout + Firestore paths: `shared/types.ts` (`storagePaths`, `collections`). Scene videos version as `v{n}.mp4`; every provider result is copied to Storage immediately.
